# Friction log

Platform friction met while building against Bee. Sources: the organizer forum, the Bee subreddit, the bee-cli 0.8.0 source (commit 84a6e8f), and the public Nectar friction log. Items marked (this build) were hit by Receipts directly.

| # | Friction | Evidence | Effect on a builder | Suggested fix |
|---|---|---|---|---|
| 1 | The BeeMCP page asks for an API key and the link that explains where to get it is dead. | r/Bee_computer "Can't connect to Claude" (2026-10-11): "the BeeMCP needs an API key, but the link to find it is dead." | MCP onboarding stalls at step one. The local `bee mcp connect` path works around it. | Restore the link, or say on the page that `bee login` is the key path. |
| 2 | Recordings under about 50 words are deleted: CAPTURING, then 404. | Organizer forum thread 45111. | A short spoken command never becomes a conversation, so designs that listen for commands lose their input. Receipts keeps its own ledger so a receipt outlives a deleted source. | Return a `deleted_short` state instead of a 404, or keep the transcript for 24 hours. |
| 3 | `/v1/threads` returns 403 `test_user_required` for normal accounts, while `bee threads` is documented in the CLI and the skill. | bee-cli docs and source (`sources/resources/threads`), probe in `docs/research/platform.md` section 1.1. | A builder reading the CLI reference plans around a feature the account cannot call. | Mark the threads commands as test-user only in `bee --help` and the skill. |
| 4 | A fact has no pointer to the conversation it came from. The fact object is `{ id, text, tags, created_at, confirmed }`. | `sources/resources/facts/index.ts:55-61`. | Provenance has to be reconstructed by searching utterances after the fact, which is exactly what Receipts does. A `source_conversation_id` on the fact would make it exact. (this build) | Add `source_conversation_id` and `source_utterance_ids` to the fact object. |
| 5 | `bee stream --json` prints the raw payload with no top-level `event` field. | `sources/commands/stream/index.ts:315,351` prints `event.data` only. | `jq 'select(.event=="todo-updated")'` matches nothing, silently. Receipts uses `--types todo-updated` and treats any event as a wake-up, then reads the to-do. (this build) | Include `event` in the JSON data, or print `{event, data}`. |
| 6 | `bee status` exits 0 when logged out. It prints "Not logged in." and returns. | `sources/commands/status/index.ts:40`. | A script that gates on `bee status && ...` proceeds logged out. Receipts gates on `bee me`, which exits 1. (this build) | Exit non-zero from `status` when there is no token. |
| 7 | `bee changed` fetches every changed id with `Promise.all` and throws on the first failure. | `sources/commands/changed/index.ts:28-35, 229-240`. | If a changed id has since been deleted, the whole feed can fail, and a tool that deletes facts (as Receipts does on a tick) can wedge its own cursor. Receipts falls back to the pending-facts list and holds the cursor. (this build) | Return ids with a `deleted` flag, or skip ids that 404. |
| 8 | A Bee to-do has no tags or metadata field. | `sources/resources/todos/index.ts:49-55`: `{ id, text, alarm_at, completed, created_at }`. | Linking a helper to-do to its fact means encoding the fact id in the text, `[rcpt:<id>]`. (this build) | Add a free `metadata` map or `external_id`. |
| 9 | Wearer speech arrives as speaker `Unknown`, and speaker names drift. | Nectar friction log, 2026-10-17. | "Who said it" cannot rely on the label alone. Receipts combines the label with other-voice count, cadence, show cues and person of the quote. (this build) | Label the wearer, for example `You`. |
| 10 | `POST /v1/todos` is reported to need `Content-Type: application/json; charset=utf-8`. | Nectar friction log. The bee-cli client sets `application/json` (`sources/client/clientApi.ts:41`). | Direct REST callers hit a rejection that the CLI hides. | Accept `application/json` with or without charset. |
| 11 | The CLI skill says `bee facts update` requires `--text`; the source fetches the stored text when it is omitted. | `bee-skill` SKILL.md "Facts" section vs `sources/resources/facts/index.ts:498-513`. | Builders pass redundant text. | Align the skill with the shipped behaviour. |
| 12 | Timestamps are epoch seconds in some fields and milliseconds in others. | `sources/commands/now/index.ts:200-211` normalizes both; todo fixtures use seconds (`resources/todos/index.test.ts:118`). | Every consumer needs a normalizer or its dates are off by a factor of 1000. (this build) | Document one unit per field, or return ISO strings. |
